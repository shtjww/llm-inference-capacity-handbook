## 5. 仿真方法全景与误差解剖

本章回答：业界到底有哪些仿真路线、各自的误差从哪来、你的问题该用哪条。读完后你应能看着任何一份仿真报告，说出它的误差藏在哪一层。


### 5.1 五条路线谱系总图

按"性能数字从哪来"分五类——粒度越细越准、也越贵：


| # | 路线 | 代表 | 性能数字来源 | 典型误差 | 数据成本 |
|---|---|---|---|---|---|
| 1 | 纯解析 Roofline | GenZ、LLM-Viewer、多数自研模拟器内核 | 逐层 FLOPs/字节 ÷ 有效算力带宽，效率因子拍经验值 | 15~30% | 零 GPU，秒级 |
| 2 | 解析 + 排队论 | 本手册三层模型 | 路线1 + Erlang C / Allen–Cunneen | λ_sat ±10~50%；P95 只给区间 | 零 GPU |
| 3 | 算子 profiling + ML 响应面 + DES | Vidur（微软，MLSys 2024） | CUPTI（NVIDIA 性能计数器接口）扫网格 profiling（逐点实测），每类算子一个随机森林（机器学习回归器，不能外推）；离散事件仿真管调度 | 网格内 1~9%；出网格崩溃 | 单卡数小时 |
| 4 | 原语实测组合 | AIConfigurator（NVIDIA，2026.01） | 不用 roofline 也不用 ML（机器学习）：拆成基本操作在真卡实测，按定义好的性能模型组合 | TPOT MAPE（平均绝对百分比误差）6~12% | 需要真卡 |
| 5 | Cycle 级软硬协同 | LLMServingSim 2.0（KAIST） | 镜像 vLLM 调度器 + ASTRA-Sim 网络仿真 + 逐层 profiler 数据驱动 | 平均 1.4~2.4% | 研究级，最重 |

**选路线就是选"你能拿到什么数据"**：误差每降一个台阶，数据成本上一个台阶。


### 5.2 代表方法解剖

**路线 3 Vidur：为什么必须是随机森林**。论文写得明确：多项式/线性回归吃不下 CUDA kernel 的非线性——tile quantization 与 wave quantization（SM 按波形整批调度，输入跨过 tile 边界时利用率阶梯跳水）、cuBLAS（NVIDIA 矩阵乘库）启发式在不同尺寸换 kernel 实现，使耗时曲线呈阶梯状。随机森林天然表达分段常数，正好吃这种形状。流程：目标卡上 CUPTI profiling 扫网格（几小时）→ 训练每类算子的响应面 → 离散事件仿真（调度、KV 管理、路由）产出 TTFT/TPOT/容量。**关键边界：随机森林不能外推**——树模型出训练范围后输出恒等于边界叶子（饱和）。所以 Vidur 的精度边界 = profiling 网格边界：网格内 1~9%，网格外不是"误差变大"而是"没有数据"。实测经验（8B 1%、14B 3%、671B 无卡 20~30%）本质即此：出网格 + 物理机制切换（EP 通信、MoE 路由不均）。后续工作（Frontier）还指出其 attention 模型过度简化时单算子误差可达 55%——算子模型本身的保真度也是边界。

**路线 4 AIConfigurator：与 Vidur 的哲学分歧**。NVIDIA 2026 年 1 月发布，路线相反：拒绝解析抽象也拒绝学习——把推理拆成基本操作，在真卡上实测每个原语，再按定义好的性能模型组合。其论文明说 Vidur/APEX 的解析抽象漏掉了框架特定开销。优势是抗框架差异（原语在真实框架里测出来），代价是每换框架/版本要重测。TPOT MAPE 6~12%，帕累托前沿（成本-性能的最优折中曲线）偏差 ≤17%。

**路线 5 LLMServingSim：误差地板在哪**。镜像 vLLM 调度器（Python 前端逐行对齐真实调度逻辑）+ ASTRA-Sim 网络后端 + vLLM 逐层 profiler 数据，支持异构卡 / P-D 分离 / EP，平均误差 1.4~2.4%。它的启示：**误差地板不在算子模型，而在调度器保真度**——调度行为不一致，算子再准也白搭。

**路线 1 纯 Roofline 的位置**。GenZ / LLM-Viewer 证明逐层解析模型量级可靠（15~30%）：回答"买什么卡"够，回答"P95 多少"不够。效率因子（0.7 / 0.75 之类）是它唯一也是最大的误差源——就是 MFU/MBU 必须锚定的问题。


### 5.3 误差来源完整解剖（自下而上五层）

所有路线的误差都能归进这五个抽屉；每条路线能捕捉的层数不同——这就是精度 1.4% → 6% → 15% → 30% 排序的原因。

- **物理层（硬件本身的非理想性）**：tile / wave quantization（输入跨 tile 边界耗时阶梯跳变，路线3捕捉，1/2漏）；cuBLAS/cuDNN kernel 启发式切换（路线3/4捕捉）；频率 throttling、HBM 有效带宽 < 标称、ECC 开销、显存碎片（所有路线都漏，靠锚定/实测吸收）。
- **算子层**：attention 二次项与实现差异（FlashAttention / PagedAttention 行为不同；Vidur 的 attention 模型曾被指出单算子 55% 误差）；EP all-to-all / TP all-reduce 通信随 batch 和拓扑变化——实测 R1：batch 10→30，decode 有效带宽 16.5→9.8 TB/s，单一常数全失效（路线5捕捉，1/2/3 漏）；kernel launch / CPU 调度开销（小 batch 时占比大，解析模型常忽略）。
- **框架层（解析模型的百慕大）**：chunked prefill 切片边界、调度器抢占、前缀缓存命中、投机解码接受率、CUDA graph 档位；路线1/2/3 全部漏掉或只能粗建模，只有实测派（4/5）能捕捉——**"同模型同卡、vLLM 与 SGLang 差 20%"主要来自这一层**。
- **系统层**：到达非泊松、服务时间重尾、准入控制行为——排队模型的近似误差（P95 绝对值差 1.5~2 倍，但方向保守、拐点位置准，见 4.2 节）。
- **方法学层（所有路线共同的生死线）**：内插 vs 外推——锚点/网格覆盖区间内，各路线都准；出区间，解析派线性漂移、ML 派饱和崩溃。外推三禁区：跨硬件代际、Dense→MoE、负载形态切换。
> **背景知识索引（“常数为什么会飘”的深造地图）**：本手册不做引擎/算子调优，但理解以下三组概念有助于判断误差从哪一层来——① **kernel 融合**：把 RMSNorm+matmul+SiLU 这类相邻算子拼成一个 kernel，省掉中间结果在 HBM 的来回搬运（典型 pattern：norm+线性层、GEMM epilogue 激活、QKV 融合、MoE grouped GEMM）——融合程度不同，同一模型在不同框架下的“框架层”效率自然不同；② **量化方法**：GPTQ（二阶补偿）/ AWQ（保护重要激活通道）/ SmoothQuant（平滑迁移）三家，AWQ 与 SmoothQuant 可组合进同一条流水线；使用顺序上 **PTQ 是默认、QAT 是兜底，不要反过来**；③ **编译路线**：Triton（tile 编程模型）/ TVM（自动调度）/ XLA 与 TorchInductor（图编译），CUDA Graph 档位差异也属此列。

**一句话总结**：1.4% 和 30% 的差距不在公式漂亮程度，在于——物理层和算子层有没有数据、框架层有没有实测、方法学层有没有出界。


### 5.4 选择决策树与两阶段工作流

手上有什么数据？
├─ 零 GPU，量级决策（买什么卡、买几张） → 路线1/2（手册+计算器），结论给区间
├─ 单卡几小时                         → 路线3 Vidur 式；或请求级快速锚定（±10~15%）
├─ 真卡 + 目标框架                     → 路线4 原语实测组合（6~12%，抗框架差异）
└─ 研究调度策略 / 软硬协同              → 路线5 cycle 级（1.4~2.4%，成本最高）

实践中最划算的是**两阶段工作流**（已被多方独立验证）：路线1海选（零成本，15~30% 误差把配置空间从几百个缩到几个）→ 云 GPU profiling 精选（对候选配置做 L1 或原语级锚定，收敛到 6~12%）。该工作流在谱系上最接近路线4的数据驱动派，区别在 profiling 粒度：请求级便宜快捷、原语级抗框架差异——预算够就下沉一层。

**配套工具说明（本手册的“第六条路线”）**：与手册配套的“大模型推理决策仿真器”走路线 2/3 混合的自研路线——解析模型 + 排队层 + 离散事件调度，在配置空间（GPU 数 × QPS × 调度策略：FCFS / 连续批处理 / P-D 分离）做网格搜索，直接生成“成本 × 吞吐 × TTFT”的**帕累托前沿**（成本-性能最优折中曲线），并支持 SLO 违约率约束下的卡数推荐。用途正是两阶段工作流的第一阶段：零 GPU 把几百个配置缩到前沿上的几个，再对前沿上的点做 L1 锚定。**读前沿图的一个暗坑（来自仿真器实战）：“全维度支配才淘汰”的规则会让单维度极端点赖在前沿上**（例如 TTFT 极低但吞吐趋零的残废配置）——看前沿先过滤这种点，否则误导选型。
